# SEO Monitor

WordPress-плагин для регулярной проверки технических SEO-настроек и данных Яндекс Вебмастера с отправкой отчётов через Telegram.

## Возможности

- проверка `robots.txt`, `sitemap.xml`, meta robots и canonical;
- контроль HTTP-кодов, редиректов и технических URL;
- поиск кириллицы в URL из sitemap;
- интеграция с API Яндекс Вебмастера через OAuth;
- ежедневный контроль индексации, диагностики и Sitemap в Яндексе;
- контроль признака отсутствующей региональности с выбираемой датой и временем проверки;
- автоматическое уведомление при критических проблемах и падении числа страниц в поиске;
- почасовые уведомления о критических ошибках;
- еженедельные SEO-отчёты через Telegram;
- команды `/start`, `/status`, `/report`, `/yandex`, `/region`, `/cyrillic` и `/help`;
- подключение получателей по защищённой ссылке;
- шифрование токена Telegram и защищённый webhook;
- обновление через публичные GitHub Releases.

## Подключение Яндекс Вебмастера

В `WordPress → Настройки → SEO Monitor` доступны два способа:

1. **OAuth с callback:** создать приложение с платформой «Веб-сервисы», правом `webmaster:hostinfo` и Redirect URI, показанным на странице плагина. Сохранить ClientID и Client secret, затем нажать «Подключить Яндекс». При наличии refresh-токена доступ продлевается автоматически.
2. **Готовый OAuth-токен:** создать приложение «Для доступа к API или отладки» с правом `webmaster:hostinfo`, получить токен и один раз вставить его в настройки. Плагин предупредит перед окончанием рассчитанного шестимесячного срока.

Логин и пароль Яндекса в WordPress не сохраняются. Client secret, access token и refresh token шифруются с помощью `AES-256-GCM` и секретных ключей WordPress.

В этом же разделе можно выбрать ожидаемый регион, дату и время однократной контрольной проверки. Дата заранее не задаётся: администратор включает проверку и выбирает будущие дату и время в настройках WordPress. После проверки результат автоматически отправляется всем получателям Telegram, а однократная задача отключается. Ежедневный монитор продолжает отслеживать изменение признака `NO_REGIONS`.

API сообщает только о наличии или отсутствии проблемы «регион не задан». Точное название принятого региона и подробный статус модерации необходимо подтвердить в интерфейсе Яндекс Вебмастера.

### 1.1.1

- Исправлена маршрутизация административных действий: ручная SEO-проверка, тест Telegram, действия Яндекс Вебмастера и управление получателями используют отдельный параметр операции.

## Выпуск обновления

1. Изменить номер версии в заголовке плагина, константе `VERSION`, `readme.txt` и `README.md`.
2. Создать Git-тег, например `v1.1.0`.
3. Опубликовать GitHub Release на основе этого тега.
4. Желательно прикрепить к релизу архив `seo-monitor.zip` с корневой папкой `seo-monitor`.

Если архив не прикреплён, updater использует стандартный GitHub zipball и автоматически приводит имя каталога к slug плагина.

После публикации релиза WordPress обнаружит новую версию при очередной проверке обновлений. Настройки Telegram, получатели и расписание при обновлении сохраняются.
